# PolyPDF working agreement

- Explain the scope of new feature work and obtain the user's approval before implementation. Continue routine fixes and verification within an approved scope.
- After approved work is complete and checks pass, publish the matching source, tag, release notes and required assets to robertmartic/polypdf. The user has authorised this release workflow; do not request approval again merely to publish the completed version.
- Verify published source against the prepared snapshot and anonymously download/hash the release assets. Keep personal documents, credentials, settings, recovery data, screenshots and generated outputs out of source and releases.
- Keep the application interface English and user conversation Croatian.
- Preserve installer identity, installation location, user preferences, documents and shortcut choices across updates.
- Maintain installer, portable and source packages, update manifests, maintenance installers and applicable file-delta packages. The new 0.1.0 baseline is full-only; future deltas must use a published version from the new version sequence.
- Test update failures as well as success. Never force an update over unsaved work, silently downgrade, or claim a failed update succeeded.
